# Схема базы данных: Университет (PostgreSQL)

## Общее описание
База данных представляет собой цифровую экосистему университета и включает 8 взаимосвязанных таблиц. Структура иерархична: **Факультеты -> Кафедры / Программы -> Студенты / Абитуриенты / Курсы**. База данных спроектирована для поддержки приёмной кампании, учебного процесса, управления персоналом и аналитики.

---

## Описание таблиц и атрибутов

### 1. Таблица: `staff` (Сотрудники)
*Описание: Хранит данные о преподавателях, деканах, заведующих кафедрами и прочем персонале.*
| Колонка | Тип данных | Ключ | Описание |
| :--- | :--- | :--- | :--- |
| id | bigserial | PK | Уникальный идентификатор сотрудника |
| fio | text | | ФИО сотрудника (разрешено к выводу) |
| post | text | | Должность (например: "Декан", "Заведующий кафедрой", "Преподаватель") |
| department_id | bigint | FK | Ссылка на `departments.id` (подразделение, к которому привязан сотрудник) |
| email | text | | Контактный email |
| phone | text | | Контактный телефон |

### 2. Таблица: `faculties` (Факультеты)
*Описание: Хранит информацию о факультетах университета.*
| Колонка | Тип данных | Ключ | Описание |
| :--- | :--- | :--- | :--- |
| id | bigserial | PK | Уникальный идентификатор факультета |
| name | text | | Название факультета |
| dean_id | bigint | FK | Ссылка на `staff.id` (текущий декан факультета) |

### 3. Таблица: `departments` (Кафедры)
*Описание: Хранит информацию о кафедрах. Кафедры принадлежат факультетам.*
| Колонка | Тип данных | Ключ | Описание |
| :--- | :--- | :--- | :--- |
| id | bigserial | PK | Уникальный идентификатор кафедры |
| faculty_id | bigint | FK | Ссылка на `faculties.id` (факультет, к которому относится кафедра) |
| name | text | | Название кафедры |
| head_id | bigint | FK | Ссылка на `staff.id` (заведующий кафедрой) |

### 4. Таблица: `programs` (Образовательные программы)
*Описание: Хранит информацию о направлениях подготовки и специальностях, предлагаемых факультетами.*
| Колонка | Тип данных | Ключ | Описание |
| :--- | :--- | :--- | :--- |
| id | bigserial | PK | Уникальный идентификатор программы |
| faculty_id | bigint | FK | Ссылка на `faculties.id` (факультет, реализующий программу) |
| code | text | | Код направления (например, "09.03.02") |
| name | text | | Название программы (например, "Информационные системы и технологии") |
| budget_seats | integer | | Количество бюджетных мест |
| paid_seats | integer | | Количество платных мест |
| min_score_prev | integer | | Минимальный проходной балл прошлого года |
| form | text | | Форма обучения (очная, заочная и т.д.) |

### 5. Таблица: `students` (Студенты)
*Описание: Хранит данные о текущих студентах университета.*
| Колонка | Тип данных | Ключ | Описание |
| :--- | :--- | :--- | :--- |
| id | bigserial | PK | Уникальный идентификатор студента |
| fio | text | | ФИО студента (Запрещено выводить в общих запросах! Только сам себе) |
| student_card_no | text | | Номер студенческого билета |
| email | text | | Контактный email (Персональные данные) |
| phone | text | | Контактный телефон (Персональные данные) |
| program_id | bigint | FK | Ссылка на `programs.id` (на какой программе обучается) |
| course | integer | | Текущий курс (1, 2, 3, 4) |
| gpa | numeric(4,2) | | Средний балл (Grade Point Average) |
| status | text | | Статус (например: "Активен", "Академический отпуск", "Отчислен") |
| source | text | | Источник поступления (например: "Бюджет", "Платное") |

### 6. Таблица: `courses` (Учебные курсы / Дисциплины)
*Описание: Хранит информацию о дисциплинах, преподаваемых в рамках программ.*
| Колонка | Тип данных | Ключ | Описание |
| :--- | :--- | :--- | :--- |
| id | bigserial | PK | Уникальный идентификатор курса |
| teacher_id | bigint | FK | Ссылка на `staff.id` (преподаватель, ведущий этот курс) |
| program_id | bigint | FK | Ссылка на `programs.id` (для какой программы читается) |
| name | text | | Название дисциплины (например, "Базы данных") |
| credits | integer | | Количество зачетных единиц (кредитов) |
| semester | integer | | Номер семестра, в котором преподается |

### 7. Таблица: `applicants` (Абитуриенты)
*Описание: Хранит данные о поступающих в рамках приёмной кампании.*
| Колонка | Тип данных | Ключ | Описание |
| :--- | :--- | :--- | :--- |
| id | bigserial | PK | Уникальный идентификатор абитуриента |
| fio | text | | ФИО абитуриента (Запрещено выводить в общих запросах!) |
| program_id | bigint | FK | Ссылка на `programs.id` (на какую программу подает документы) |
| ege_score | integer | | Суммарный балл ЕГЭ |
| submitted_date | date | | Дата подачи документов |
| status | text | | Статус заявления (например: "Подано", "В очереди", "Зачислен") |
| source | text | | Источник подачи (например: "Онлайн", "Лично") |

### 8. Таблица: `enrollments` (Успеваемость / Журнал оценок)
*Описание: Связывает студентов и курсы для фиксации успеваемости (оценки, посещаемость).*
| Колонка | Тип данных | Ключ | Описание |
| :--- | :--- | :--- | :--- |
| id | bigserial | PK | Уникальный идентификатор записи |
| student_id | bigint | FK | Ссылка на `students.id` (студент) |
| course_id | bigint | FK | Ссылка на `courses.id` (дисциплина) |
| semester | text | | Семестр (например: "Осенний 2026", "Весенний 2026") |
| grade | numeric(4,2) | | Полученная оценка (например: 4.5, 3.0) |
| passed | boolean | | Сдал ли экзамен/зачет (true/false) |
| attendance | integer | | Процент посещаемости (например: 85) |

## Связи и ограничения (Foreign Keys)

**Иерархическая структура:**
1. **Факультеты и Сотрудники:**
   - `faculties.dean_id` (M:1) -> `staff.id` (Один сотрудник может быть деканом только одного факультета).
   - `departments.head_id` (M:1) -> `staff.id` (Один сотрудник может заведовать кафедрой).
   - `staff.department_id` (M:1) -> `departments.id` (Многие сотрудники работают на одной кафедре).

2. **Факультеты и Структура:**
   - `departments.faculty_id` (M:1) -> `faculties.id` (На одном факультете много кафедр).
   - `programs.faculty_id` (M:1) -> `faculties.id` (Факультет реализует множество программ).

3. **Образовательный процесс:**
   - `students.program_id` (M:1) -> `programs.id` (На одной программе обучается много студентов).
   - `applicants.program_id` (M:1) -> `programs.id` (Много абитуриентов подают на одну программу).
   - `courses.program_id` (M:1) -> `programs.id` (Программа включает множество курсов).
   - `courses.teacher_id` (M:1) -> `staff.id` (Один преподаватель может вести множество курсов).

4. **Журнал успеваемости:**
   - `enrollments.student_id` (M:1) -> `students.id` (Один студент имеет много записей об успеваемости).
   - `enrollments.course_id` (M:1) -> `courses.id` (Один курс имеет много записей об успеваемости).
   - *Примечание:* Связь `enrollments` между студентами и курсами является связью "многие-ко-многим", реализованной через промежуточную таблицу.

## Важные правила для LLM (Политика безопасности данных)
1. **Разрешено выводить:** ФИО преподавателей, деканов, сотрудников.
2. **Запрещено выводить (без строгого ограничения по ID текущего пользователя):** ФИО, email, телефон студентов и абитуриентов.
3. **Правило агрегации:** Все запросы, касающиеся студентов или абитуриентов (в том числе средние баллы, количество студентов, статистика приема) должны возвращать данные в **агрегированном (обезличенном) виде** (например, COUNT, AVG, SUM), без раскрытия `fio`, `email` или `phone`.
4. **Роли пользователей:**
   - **Абитуриенты** ищут данные в `programs` и `applicants` (в агрегате).
   - **Студенты** ищут свои данные в `students`, `courses` и `enrollments`.
   - **Преподаватели** ищут данные в `courses` и `enrollments` (агрегированная статистика по группам).
   - **Администрация** работает с `faculties`, `departments`, `staff`, `programs`, `students` и `enrollments`.
